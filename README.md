# pokesim

チャンピオンズの技・種族データと同梱の対戦エンジンを使った、シングル対戦用のAIシミュレーター。

## 実行

プロジェクトのルートで実行する。

```text
node scripts/validate-teams.cjs
node scripts/battle-from-json.cjs
npm test
node scripts/audit-move-effects.cjs
```

チームは `teams/team-a.json` / `teams/team-b.json` に日本語名で設定する。技の利用制限に違反したチームは対戦開始前に拒否し、別の技への自動置換はしない。

## シングルの技制限

対戦形式・フォーマット・場に出る数・技の利用制限を `scripts/battle-rules.cjs` に集約している。通常のエンジンの合法性チェックに加え、このプロジェクトで利用できる技かを検証する。

現在のマスターでは次の9技を登録・選択・相手の構成予測から除外する。

- このゆびとまれ、いかりのこな
- おさきにどうぞ、さきおくり、サイドチェンジ
- てだすけ、アロマミスト、コーチング、ドラゴンエール

味方だけを対象にする `adjacentAlly` の技は共通の対象判定で制限する。自分や相手を対象にできるがシングルで失敗する5技は、形式別のID一覧で制限する。技マスター・習得表・エンジンの技定義は保持し、予測候補の生成時にフィルターを適用する。

ワイドガード、ファストガード、なみのり、じしん等はシングルでも効果があるため使用できる。いやしのはどう・さいはい等も相手に使えるため、相手を助ける不利益を含めて評価する。「ダブルでよく使われる」という理由だけでは制限しない。

AIの選択でも利用制限を適用し、元の技スロット番号を維持する。無効なチーム等からダブル専用技しか選べない要求が来た場合は、技を実行せず理由付きエラーにする。複数の場のポケモンを含む要求も拒否する。

## 技の評価

技の評価では、アンコール・かなしばりの成功条件、持ち物交換前後の損益、おいかぜ後の行動順、攻撃による確率的な能力上昇を比較する。未公開の特性・持ち物は公開情報から作った構成候補ごとに評価し、その予測を公開状態へ書き戻さない。評価の重みや複数ターン先の近似については `battle-audit.md` の最新記録を参照。

ちょうはつ・やどりぎ・あくびは既存状態への再使用や即時解除を判定する。状態異常を付ける主効果と追加効果は、火力・速度・行動可能性・継続ダメージや回復の損益を比較する。ねごとは成功して不利になる呼び出しも平均へ含める。砂・雪は双方のタイプ・特性と自分の控えを考慮し、まもる系は個別の接触時効果、貫通後の被害と連続成功率を反映する。

## 将来ダブルに対応する際の拡張点

`BATTLE_MODES.doubles` には場に出る数と、シングル専用の技制限を適用しない定義を用意している。ただし現在は `implemented: false`、`format: null` で、対戦開始を明示的に拒否する。設定だけを変えてダブルAIが動作するという意味ではない。

ダブル実装時は以下を追加し、検証後に形式を有効にする。

1. 同梱エンジンで利用できるChampionsのダブル用フォーマットと選出ルールを設定する。
2. 現在1体分の公開状態・技要求・評価を扱う処理を、場の各位置と味方・相手の対象指定に対応させる。
3. 味方への補助、範囲攻撃、交代、2体の同時選択を扱う評価・行動生成を実装する。
4. 形式別のチーム検証、対象の合法性、各技の味方・相手への効果、終局までの対戦をテストする。

技制限の定義を共有するため、チーム変換・検証・AI選択・構成予測のそれぞれに禁止技一覧を書き直す必要はない。対応状況は `battle-effect-coverage.md`、過去を含む検証記録は `battle-audit.md` に記録する。
